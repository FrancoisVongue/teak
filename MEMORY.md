# Память в orto: Region и Ref

Краткая сводка модели памяти — то, к чему мы пришли. Не история, а итог.

## Два понятия, и всё

Для пользователя мир памяти — ровно два понятия:

1. **`Region`** — кусок памяти со временем жизни. Владелец.
2. **`Ref[T]`** — gen-проверяемая ссылка на ячейку(и) в регионе.

Третьего нет. `Own` (владение) пользователю не показываем — это внутреннее
(см. ниже).

## Region — владелец

- Создаётся: `region(N)` (куча), `stack_region(N)` (стек, N литерал),
  `aligned_region(N, A)` (выровненный).
- Привязывается к scope: `arena r = region(N)`.
- **Освобождается сам** в конце своего scope. Никаких ручных free.
- Линеен как владелец (не копируется, не возвращается из функции), но
  свободно передаётся в функции как наблюдатель.
- **Функция берёт `Region` только если аллоцирует.** Если просто читает или
  обходит данные — берёт `Ref`, а не регион (ссылка сама знает свой регион
  по номеру слота).

Картинка: регионы — это строки в глобальной таблице памяти. Каждая строка
принадлежит своему scope и чистится сама.

## Ref[T] — ссылка на ячейки

**Один тип ссылки.** Коробка = `Ref` длины 1, буфер = `Ref` длины N — это
один и тот же тип, длина в рантайме. (`Array` как отдельное имя/тип — мёртв.)

- Создать: `ref(r, v)` — одна ячейка = v; `ref(r, n, init)` — n ячеек;
  `ref(r, [a, b, c])` — из значений.
- Прочитать: `r[i]` — **abort**, если регион мёртв или вышли за границу.
- Записать: `r[i] := v`. Одна ячейка → `r[0]`.
- Безопасно: `try_at(r, i) -> Option[T]` — `None` вместо abort.
- `len(r)`, `slice(r, lo, hi)`.
- Копируемая, передаётся и хранится свободно. Может протухнуть.

**Несколько типов в одном Ref?** Нет — `Ref[T]` всегда на один T. Нужно
разнородное — делаешь T суммой или кортежем: `Ref[Shape]`, где
`Shape = enum { ... }`. Спец-«гетерогенного массива» нет.

## Почему это безопасно, и почему Own — внутреннее

Регион gen-checked: у слота есть счётчик поколения. Протухшая ссылка
(регион сброшен) → **abort**, ровно как выход за границу массива, а не
тихий use-after-free.

Поэтому **владелец — регион, а не пользователь**. Кто и когда освобождает —
внутреннее дело компилятора. Пользователь только держит `Ref` и называет
регионы (= задаёт время жизни). Это и есть «Own как внутреннее понятие» —
никаких `own`/`take`/`drop` для памяти.

## Откуда компилятор знает размер ячейки

Не считает сам. Две вещи: **мономорфизация** (к codegen'у T всегда
конкретный) + **компиляция в C**. Индексация → `((T*)(buf+off))[i]`, шаг =
`sizeof(T)`, который считает компилятор C. Enum компилится в C-union
фиксированного размера (самый большой вариант + тег), поэтому все значения
одного enum'а одного размера — `Ref[Shape]` работает. Цена: ячейка занимает
размер наибольшего варианта (большой вариант боксь через `Ref`, если жалко).

## Рекурсивные данные

Через ссылки: `enum Tree { Leaf, Node(int, Ref[Tree]) }`,
`enum List { Nil, Cons(int, Ref[List]) }`. Узлы живут в регионе, поле-ссылка
фиксированного размера (хендл) разрывает цикл по размеру. Регион умер — всё
дерево разом.

## Изменение на месте (присваивание по пути)

Слева от `:=` — любое **место**: переменная, ячейка, поле:
`x := v`, `a[i] := v`, `s.f := v`, `r[i].f := v`, `s.f.g := v`.
Пишет прямо в C-lvalue, **без копирования** структуры целиком.

- Через Ref-индекс (`r[i].f := v`) — пишем региональную память через хендл,
  `mut` не нужен.
- Чистый field-путь по локали (`s.f := v`) — мутирует локаль, корень должен
  быть `let mut`.
- В линейное поле присваивать нельзя (затёрли бы ресурс → утечка).

## Контейнер НЕ хранит свой регион

Контейнер (Vec, HashMap) — это **чистые данные**: `Ref`-хендлы + счётчики.
Региона внутри нет. Аллоцирующие методы **берут регион**: `push(v, r, x)`,
`insert(m, r, k, v)`. Владелец — `arena` у вызывающего.

Почему не хранить: ссылка на регион внутри контейнера создала бы **связь
времён жизни** («контейнер валиден, пока жив тот регион») — а отслеживать
это и есть машинерия lifetime'ов (как в Rust), которую мы выкинули. У
контейнера-как-данных такой связи нет: его валидность = gen-проверяемая
валидность хендлов. Регион умер → доступ абортит, безопасно.

## Внешние ресурсы — отдельная ось

Файлы, сокеты и т.п. — **не** память региона. Это **линейные типы**:
`linear struct Socket { fd: int }` + обязательная `fn drop_Socket(s) -> int`.
Нельзя скопировать, нельзя положить в data position обычной структуры.
`drop(x)` явно или авто-drop в конце scope. У них **нет gen-проверки** —
поэтому нет и копируемой ссылочной формы (протухшая копия = тихий
use-after-close, который нечем поймать). Это и есть причина, по которой
регион получает копируемый `Ref`, а сокет — нет.

## Слои: что в языке, что в библиотеке

- **Язык (минимум, безопасный):** `Region` + `Ref[T]`. Это и есть
  типизированный массив-примитив — потому что он несёт безопасность
  (построить его из сырых байт = unsafe в ядре, чего мы не хотим).
- **Стандартная библиотека (поверх, без unsafe):** `Vec[T]` (растущий),
  `Map[K,V]`, ring buffer и т.д. — обычный orto-код над `Region` + `Ref`,
  рост = выделить `Ref` побольше и скопировать.
- **Поведение по типу** (сравнение, хэш для ключей) — впрыском функции:
  `sort(xs, cmp)`, либо `cmp`/`hash` лежат замыканием прямо в структуре
  контейнера. Никаких классов типов.
