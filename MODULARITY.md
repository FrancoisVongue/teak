# orto — модули и видимость

Минимальный атом модульности: **namespace + `use` + `pub`**. Не пакет-менеджер (это молекула, §2) — только то, из чего остальное собирается.

## Namespace = файл

- Файл `foo.orto` неявно образует namespace `foo`. Блок `namespace a::b { ... }` задаёт явный путь; несколько файлов могут дополнять один namespace.
- Имена мангелятся в C как `a__b__name`. Билтины (`Handle`, `Region`, `Option`, `Result`, `Some`/`None`/`Ok`/`Err`, `byte`, `main`) не мангелятся.
- Драйвер грузит модули, проходя по `use`-объявлениям; путь поиска — каталог исходника, затем `ORTO_STD` (по умолчанию `std/`).

## Видимость: `pub`, по умолчанию **private**

- Любая top-level декларация (`fn`, `struct`, `enum`, `resource struct/enum`, `type`, `const`, `extern fn`) по умолчанию **видна только в своём namespace**.
- `pub` экспортирует её: `pub fn`, `pub resource struct`, `pub const`, …
- `pub enum` экспортирует и свои конструкторы (без них тип бесполезен снаружи).
- Почему default-private: публичная поверхность модуля видна в коде явно (§5.2), а не «всё неявно открыто». Рефакторить внутренности можно, не ломая клиентов.

## Enforcement — без обхода

Видимость проверяется в резолвере (`resolve.ml`), на **обоих** путях доступа:
1. **`use other::{x}`** — `x` обязан быть `pub` в `other` (или re-export). Иначе: *"x is private to other"*.
2. **Qualified `other::x`** — то же правило (иначе qualified-ссылка обходила бы импорт-проверку).

Билтины и локальные имена проверке не подлежат. `pub use a::{x}` (re-export) делает `x` публичным и в этом namespace.

**Разделитель namespace — `::`, не `.`** Член namespace — `net::listen`; `.` — доступ к полю (`obj.field`). Это сознательно разные оси: одна и та же `.` не должна значить «член namespace» в одном месте и «поле записи» в другом (§5.2 — `.`/`[]` не делают разное по контексту). Поэтому НЕ TS-стиль с точкой; `::` для namespace, `.` для поля.

Enforcement — чисто на уровне orto. Вся программа собирается в один `.c`, поэтому C-`static` ничего не огораживает; маркер `static` в выводе — возможная косметика на потом, не механизм.

## Что НЕ сделано (сознательно / отложено)

- **Пакеты/иерархия**: остаёмся на плоских файлах-namespace'ах. Иерархия (`std/sys/io.orto`) — при необходимости, по соглашению «путь файла = путь namespace».
- **Видимость полей struct**: поле доступно, если доступен тип (отдельного контроля полей нет — проще; добавить per-field `pub` можно позже).
- **Сужение stdlib до private**: ретрофит пометил `pub` весь top-level библиотек (`std/*`, `sys`, `iouring`, `str`, …) — их публичный API. Ужать настоящие внутренние хелперы до private — отдельный проход (нужен per-function взгляд; ждёт новых stdlib-модулей от других треков).
