orto — карта понятий компилятора

Что есть в языке и в компиляторе, как оно вложено, где красиво и где пока шероховато. Чем больше зелёного — тем ортогональнее модель; жёлтое / красное — кандидаты на чистку.

чисто / ортогонально работает, шероховато дыра / долг

1 · Слои компилятора

Каждый слой — отдельный файл. AST/Typed AST — общие данные между.

  • lex · char → token ~150 строк
  • parse · token → AST (expr/decl) ~600 строк
  • check · AST → Typed AST + анализы ~1660 строк, самый большой
  • mono · monomorphize generics → concrete ~300 строк
  • emit · Typed AST → C99 ~940 строк, диспатчи по типам

2 · Типы значений

Копируемые (data)

  • Примитивы без вопросов
    • int · 32-bit signed
    • bool · хранится как int
  • Композитные плоские данные
    • struct Name { ... } · record
    • enum Name { ... } · ADT с конструкторами
    • + type_params [T, U, ...] для дженериков
  • Функциональные указатели функций
    • fn(args) -> ret
  • Heap-handles (копируемые ручки в чужую память)
    • Array[T] · region-backed gen-check + bounds
    • Buf[T] · stack-backed никаких проверок, C-семантика
  • Built-in
    • Option[T] · Some(T) | None privileged: имена Some/None зарезервированы

Линейные (owning)

  • Region · arena с буфером и gen-таблицей единственный linear примитив
    • Линейный · нельзя копировать, можно move (как файл)
    • Auto-drop на scope-exit · один free(buffer), gen++
    • Header переживает buffer leaks 32 байта per region, v1
Право «иметь не более одного владельца» носит только Region. Всё остальное копируемо — это просто данные.

3 · Где какие типы разрешены

  • Top-level позиции всё можно
    • тип переменной (let x: T = ...)
    • тип параметра функции
    • тип возврата функции
  • Data позиции линейное запрещено
    • поле struct
    • аргумент конструктора enum
    • type argument любого TyApp
    Закон ловит struct A { r: Region }, Option[Region], Array[Region] — всё это compile error.
  • Generic параметр (TyVar) предполагается копируемым
    Сейчас fn dup[T](x: T) можно вызвать с T = Region, и внутри функции компилятор не видит линейности. На практике не возникает потому что Region обычно явно named, но это теоретическая дыра.

4 · Операции памяти

Создание

  • region(N) → Region N байт buffer
  • array(r, N, init) → Array[T] fill mode
  • array(r, [v0, ..., vN]) → Array[T] literal mode
  • buf(N, init) → Buf[T] N — литерал
  • [v0, ..., vN] → Buf[T] stack literal

Доступ

  • a[i] · read element emit диспатчит Array vs Buf
  • a[i] := v · write element тот же диспатч
  • len(a) · возвращает int общий .len
Array проверяет gen + bounds, Buf — нет. Один синтаксис, два рантайма. Это не плохо, но дубликат в emit — кандидат на объединение через runtime tag или helper-функции.

5 · Управление потоком

  • Всё — выражения, нет statements
  • if cond { ... } else { ... } · ветки возвращают значение
  • match expr { Pat => body, ... } · только ADT
  • let x [: T] = expr; body · scope-bound binding
  • expr; body · через парсер становится let _ = expr; body
  • let _ = linear_value переименовывается в _drop_N в check.ml
    Это маленький хак чтобы binding получил auto_drop и было место куда повесить free. Работает, но имя «_drop_N» — это compiler-internal naming в исходнике, проникающее в C.

6 · Анализы в check.ml

  • Inference (Hindley-Milner light)
    • TyMeta · unification variable
    • unify · type matching
    • zonk · resolve metas in tree типы и подвыражения зонкаются в разных местах
    • нет let-полиморфизма, monomorphization делает mono.ml
  • Линейность
    • is_copyable · по типу единая функция
    • ty_contains_own имя устарело: проверяет linear, не Own
    • Запрет linear в data position
    • Param-wrap: let p = p; body для Region-параметра, чтобы свернулся auto_drop трюк через TELet
  • Move analysis (check_moves)
    • live set: name → ty
    • consume_arg в move-позициях
    • Tail-position consume для bare TEVar non-copyable
    • Ветки if/match должны сходиться в одном live set
    • shadowing: outer состояние save/restore
    • divergence error: программист пишет let _ = x вручную чтобы выровнять
  • Auto-drop
    • Для Region: scope-exit emits free buffer + gen++
    • Для Array/Buf: ничего — это просто данные
    • Эмит free(...) зависит от типа binding'а if/else по конструктору TyApp

7 · Мономорфизация и emit

  • mono.ml
    • Walk начиная с main
    • На каждый use generic функции с конкретными ty list создаётся специализированная копия
    • mangle_ty · Option_int, Array_bool, fn_int_to_int и т.д.
    • структурно
  • emit.ml
    • Runtime structs: Region_header, Region, Array_T, Buf_T
    • Forward decls → fn typedefs → struct defs → fn defs
    • Топологическая сортировка struct'ов для C (поле by-value требует размер)
    • Alpha-rename let/match-arm bindings (shadowing → unique C name)
    • параллельные таблицы для Array и Buf instantiations

8 · Дженерики

  • Параметры типа на функциях и типах: fn f[T](x: T), struct Pair[A, B]
  • Параметрический полиморфизм, без классов типов
  • Никакой подтиповости
  • Monomorphization создаёт по копии на каждую инстанциацию
  • одна ось, никаких variance/bounds

⚠ Шероховатости (что в коде, но не блестит)

  • Имя ty_contains_own устарело · проверяет любой linear builtin (только Region теперь), а имя про Own. Переименовать → ty_is_linear или ty_contains_linear.
  • Дубликат validate_ty / validate_ty_for_ascription · TODO #1 в TODO.md. Два почти одинаковых обхода типов. Унификация через единый env-объект.
  • Параллельные таблицы в emit для Array и Buf · array_types_order, buf_types_order, mangle-функции, forward-emit. Можно объединить через generic "boxed handle" список.
  • Auto-drop через let p = p; body wrap · трюк для param-Region. Работает, но это «синтетический let» который через alpha-rename становится валидным C. Можно ввести отдельный TEDrop узел в Typed AST — чище.
  • let _ = linear → renamed _drop_N · аналогично — рабочий хак, но имя протекает в C-output.
  • Option как privileged ADT · имена Some/None зарезервированы, тип Option инжектируется встроенным. Сейчас Option используется только внутренне (look на массиве не вернул — wait, look удалён!). На самом деле Option не используется compiler-операциями больше — это просто библиотечный тип, который можно дать пользователю определить самому или оставить встроенным.
  • Generic-T copyability дыра · is_copyable (TyVar _) = true. Если кто-то проедет Region через generic функцию, внутри линейность не отслеживается. Лечится либо запретом Region в TyVar position, либо post-mono check.
  • Region_header утечка · заголовки регионов накапливаются. Для long-running программ — рост. Лечится pool allocator для header'ов.
  • Двухуровневый диспатч a[i] · emit разбирает Array vs Buf через match по типу. Это случается в TEIndex, TEAssignIdx. Можно вынести в helper-функцию.
  • Pattern bindings не имеют типа в Typed AST · check_moves считает типы заново через ctor info при анализе match. Если бы pattern несли типы — было бы чище.
  • Tail-position проверка через in_tail bool · добавлен в check_moves. Маленький контекст-парам. Работает, но напоминание что move-семантика «зависит от того где ты в дереве».

📐 Что красивого получилось

  • Одна ось линейности — только Region. Всё остальное копируемо.
  • Один heap-примитив — Region. Внутри bump-allocator.
  • Array и Buf — оба «handles». Различаются runtime и safety, но синтаксис общий.
  • Все expression — нет statement/expression split. Match и if возвращают значения как любое выражение.
  • Запрет linear в data — один закон, не каталог правил.
  • Generics параметрические, monomorphized. Никаких variance, type classes, traits.
  • Никаких lifetimes, никакого borrow checker'а. Безопасность через runtime gen (Array) или responsibility (Buf).
  • Видимая семантика: каждый malloc/free в C можно проследить до конкретного выражения в orto.
